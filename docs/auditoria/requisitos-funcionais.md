# Requisitos funcionais e situação no website

Auditoria de 16/11/2026 sobre `origin/CRUD`, commit `5e7c30930cca7f3ef7ee8257b768e451d6bed00e`, na branch `feature/verificacao-crud`.

A fonte é o arquivo **Resumo Técnico (1).pdf**, seção 6, páginas 15 a 30, confrontada com o código e os testes locais. As histórias de usuário das páginas 40 a 46 complementam os critérios. O documento tem **28 RF**: vai de RF-001 a RF-029, mas **não apresenta RF-023**. A numeração foi preservada. A situação “Pendente” das histórias foi reavaliada pelo comportamento atual do repositório.

**Resultado: 1 atendido no escopo local, 19 parciais e 8 ausentes.** Uma tela ou botão existente conta como evidência de interface; a aprovação completa exige também persistência e regras de negócio. A lista do trabalho restante está em [pendências funcionais](pendencias-funcionais.md).

## Como interpretar a lista

“Atendido localmente” descreve o comportamento observado no checkout do código auditado, sem certificar a versão publicada. “Ausente” indica que não foi encontrada implementação operacional no código inspecionado. “Parcial” inclui tanto funções com backend incompleto quanto protótipos que têm apenas interface. Os 27 RF parciais/ausentes precisam de trabalho para cumprir integralmente o resumo técnico.

A evidência automática e os limites da verificação estão no [relatório da auditoria](relatorio-crud.md). As lacunas sem teste específico de navegador foram verificadas por leitura dos arquivos, rotas e schema indicados na tabela; não foram contabilizadas como testes executados.
